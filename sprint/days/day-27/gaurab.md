# Day 27 — Gaurab

**Objective:** Turn the Day-24 search findings into live Play copy and a staged iOS keyword update — every swap justified by a real term — and give the quiet gyms one polite bump.
**Total time:** ~2.5h

## Task 1 · 🔥 Run the ASO iteration from the Day-24 findings (90–110 min)

**Why:** Day 24 wrote down exactly which phrases search confirmed and which died. Acting on it within the sprint — instead of "next time" — is the difference between a data pull and a growth loop.
**Where:** play.google.com/console + App Store Connect; Growth Tracker.
**Tools:** Play Console, ASC, the Day-24 one-pager (copy in READY/), Growth Tracker (`Store-Android`, `Store-iOS`), `buzzend-marketing/00-strategy/what-is-buzzend.md` (approved wording).

**Steps:**
1. Open the Day-24 one-pager and take ONLY its 3 recommended phrase changes — resist adding "while I'm in here" edits; changes we didn't plan teach us nothing.
2. **Play:** adjust the short and/or full description to make those swaps — drop the DIED phrases, work the GREW/NEW terms in naturally. It must still read like a human wrote it; approved wording only, banned words stay banned. Save — Play edits go live within hours, no release needed.
3. Careful with the running experiment: if the Day-17 experiment is testing a listing text field, don't touch that same field — swap only in the other one and note why. One variable per test, always.
4. **iOS:** rebuild the keyword string with the same logic (no spaces after commas, no words already in title/subtitle) and STAGE it in App Store Connect for the next version. Do NOT push a release just for keywords — no product changes this sprint. If no version is open, save the string in `Store-iOS` marked "ready for next release".
5. Log before/after in the tracker: every changed field, old → new, dated, with the Day-24 term that justified it.
6. Once the Play edit is live, read the listing on your own device — no truncation surprises, no robotic sentence. Screenshot and file it next to the Day-17 verification shots.

**Deliverable:** Updated Play descriptions live, new iOS keyword string staged, dated before/after log in the tracker.
**Done when:** All 3 planned swaps are made (and nothing else), each has a justifying term logged, and the live Play listing reads clean on-device.
**Depends on:** Gaurab · Day 24 · Task 1 (the findings this iteration acts on).

## Task 2 · 🟡 Gym-pilot follow-ups — one polite bump each (30–40 min)

**Why:** Gym owners live in their DMs during dead hours, not when we message. One friendly bump 5 days later is normal business manners; a second one is pestering — so this is the only bump.
**Where:** The same routes the Day-22 pitches went out on; `Outreach` tab.
**Tools:** Phone, Growth Tracker.

**Steps:**
1. Open the 3 gym rows in `Outreach`. Anyone who replied already gets a real conversation, not a bump — answer them first and log it.
2. For each gym still quiet after 3+ days: send ONE short, warm follow-up in your own words — reference the original idea in half a line, add one new concrete detail (e.g. "the Squad Squats challenge is live now, you can see a real leaderboard before deciding"), and make it easy to say no.
3. No guilt lines, no "just checking in" filler, no third message ever. If they stay quiet after this, the row closes as "no response — closed" on Day 30.
4. Update each row: bump date, wording used, status.

**Deliverable:** One logged follow-up per quiet gym, replies handled first.
**Done when:** Every Day-22 gym row shows either an active conversation or exactly one dated bump.
**Depends on:** Gaurab · Day 22 · Task 1 (the pitches being followed up).
