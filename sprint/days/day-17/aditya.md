## Task 1 · 🔥 Edit day — 2 masters + platform variants for IG/TikTok/Shorts (75–90 min)

**Why:** Two posts a day across three platforms dies the day a caption sits under TikTok's icon rail or a hook hides behind the Shorts title bar. Today you cut tomorrow's pair AND make the safe-zone pass a habit, so every master ships watchable everywhere.
**Where:** CapCut; source footage in `buzzend-footage/sprint2-batch1/`.
**Tools:** CapCut, the batch-1 take log, `buzzend-marketing/07-scripts/how-to-write-a-script.md`, `buzzend-marketing/16-templates/workflow-templates.md` (checklist #7), shared drive.

**Steps:**
1. Cut masters 3 and 4 from batch 1 — the two remaining concepts. Same discipline as always: hook on frame 1, PROOF wide, one CTA, auto-captions proofed, 15–30s, 1080×1920.
2. Safe-zone pass per master, per platform: IG Reels (bottom ~320px and right rail covered by UI), TikTok (right-side icon column + bottom caption zone), YouTube Shorts (top title area + bottom bar). Check every text layer and the counter itself against all three.
3. Where a master passes all three zones untouched, note "master serves all 3" in the tracker. Where text or the counter collides, export a variant with layers nudged into the safe middle — don't crop the person or the counter.
4. Self-check against checklist #7 (real counts, one CTA, no banned words), then drop everything in **READY/**: `day17-master-3-<concept>.mp4`, `day17-master-4-<concept>.mp4`, variants named `-ig` / `-tiktok` / `-shorts` only where they exist, + covers.
5. Log in the tracker which file goes to which platform slot — the row should read like a shipping label, not a puzzle.

**Deliverable:** Two masters + any needed platform variants + covers in READY/, mapped to platforms in the tracker.
**Done when:** For each of tomorrow's two slots, the tracker names exactly one file per platform and nothing important sits under platform UI.
**Depends on:** Aditya · Day 16 · Task 1 (batch-1 footage).

## Task 2 · 🟡 Film 3 raw screen recordings of the real Buzzend workout screen (60–75 min)

**Why:** More raw screen material was requested and we barely have any: `refrence-asset/` holds one 19s clip with promo text burned in (`refrence-asset/sample_video_with_landmark_promotional.mp4`) — useless for an App Store preview, which must show app UI only. Clean recordings feed the Day-22 preview draft AND give every future edit a real in-app proof shot.
**Where:** Your filming spot; recordings made on your own phone.
**Tools:** Phone (Buzzend + built-in screen recording), prop, shared drive, this repo's `refrence-asset/` folder.

**Steps:**
1. §40 pre-flight: test squats, push-ups, and jumping jacks on this exact phone in this position — the recordings must show real counting, so a miscount means swap the exercise and flag it.
2. Start the phone's screen recording, start a Buzzend workout, prop the phone, and do a real set — the recording captures the live workout screen: the moving skeleton, the count climbing, coaching cues as they appear. One recording per exercise, 25–40s each.
3. NO frames, NO added text, NO editing beyond trimming dead air at the ends. These must stay raw — Apple's rule for previews is actual app UI only, and our own rule says raw screens are material, never posts (they get framed before any social use).
4. Watch each back: count readable, count correct, no notification banners or personal info on screen. Re-record anything dirty.
5. Save all three into this repo at `refrence-asset/` named `raw-screen-<exercise>-01.mp4`, and drop copies in **READY/** named `day17-rawscreen-<exercise>.mp4` so the team can grab them. Log all paths + verified counts in the tracker.

**Deliverable:** 3 clean raw workout-screen recordings in `refrence-asset/` and READY/, counts verified and logged.
**Done when:** Each recording shows an unedited Buzzend workout screen with a genuine count and could be dropped straight into an App Store preview timeline.
