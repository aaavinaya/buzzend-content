# Day 17 — Gaurab

**Objective:** Ship the Sprint-2 metadata round on both stores — the approved iOS set into App Store Connect, a search-terms-driven Play refresh — and start one clean Play listing experiment.
**Total time:** ~2.5–3h

## Task 1 · 🔥 Ship the store metadata round on both stores (100–120 min)

**Why:** Sprint 1 left us a gift: an approved iOS metadata set and two weeks of real Play search terms. Putting both live is the highest-leverage acquisition work of the week — store pages sell 24/7, posts sell for a day.
**Where:** App Store Connect + play.google.com/console.
**Tools:** ASC login (access requested Day 16), Play Console login, Growth Tracker (`Store-iOS` metadata log, `Store-Android`, `Sprint2-Baseline` search terms), `buzzend-marketing/00-strategy/what-is-buzzend.md` (approved wording).

**Steps:**
1. Start from yesterday's `Store-iOS` next-step line (Day 16 Task 2 wrote it). Open App Store Connect.
2. **iOS:** take Avinaya's approved set — title, subtitle, and the keyword string — from the tracker metadata log in `Store-iOS` (the Day-14 string is marked "ready for next release"). Enter it into the next app version in ASC exactly as approved: no spaces after commas in the keyword string, no words repeated from title/subtitle. If a version is already in progress, stage it there; do NOT push a product release just for keywords — no product changes this sprint.
3. If ASC access still hasn't landed: write the exact field-by-field entry list (title / subtitle / keyword string, character counts) into the shared drive **READY/** folder so it ships the moment access lands, then continue with Play — nothing waits.
4. **Play:** refresh the short and full description using the Sprint-1 search-terms snapshot in `Sprint2-Baseline`: keep the terms real people typed, drop phrases that never appeared, work the surprise terms in so it still reads like a human wrote it. Approved wording only; banned words stay banned. Play edits go live within hours, no release needed.
5. Log before/after in the tracker: old vs new for every field you touched, dated, with the search term that justified each swap.
6. Once the Play edit shows live, read the listing on your own Android device: short description intact, no robotic keyword sentence, full description truncates cleanly at "Read more". Screenshot and file it.

**Deliverable:** iOS approved set entered/staged in ASC (or its entry list in READY/), refreshed Play listing live, before/after logged in the tracker.
**Done when:** Both stores show (or have staged) the new metadata and the tracker holds a dated old-vs-new log for every changed field.

## Task 2 · 🟡 Start one new Play store-listing experiment (40–50 min)

**Why:** Play experiments are the one place the store itself tells us what converts. Sprint 1 tested a feature-graphic headline; Sprint 2 gets one new, clean test — one variable, never two.
**Where:** Play Console → Grow → Store presence → Store listing experiments; `Experiments` tab.
**Tools:** Play Console, Growth Tracker, `store-assets/android/feature-graphic-1024x500.png`, `store-assets/android/phone/` (the screenshot set), `buzzend-marketing/16-templates/planning-templates.md` (template 13).

**Steps:**
1. Pick ONE variable: screenshot order (move the challenge/leaderboard screen from `store-assets/android/phone/` to position 1) OR a new feature-graphic headline (duplicate `store-assets/android/feature-graphic-1024x500.png` and change only the headline — approved wording, existing screens, no banned words).
2. Check the shared drive **READY/** folder first — if a fresh variant asset is already sitting there, use it; if not, make the minimal version yourself in 10 minutes and continue.
3. Create the experiment: 50/50 split, metric = first-time installers, start it.
4. Log the `Experiments` row per template 13: **Hypothesis** → **Change** (old vs new, date) → **Metric to watch**. Note the earliest sensible check-in: Day 23.
5. Drop the variant you used in **READY/** — Avinaya reviews async; fixes go out as follow-ups, nothing waits.

**Deliverable:** One running Play experiment + its `Experiments` row + the variant in READY/.
**Done when:** The console shows the experiment as "running" and the Experiments row names the single variable being tested.
**Depends on:** Gaurab · Day 17 · Task 1 (the refreshed listing is the experiment's control).
