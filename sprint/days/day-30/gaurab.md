**Steps:**
1. Re-read `publishing-sop.md` top to bottom with the Sprint-2 evidence open beside it. You're editing a living doc, not rewriting it — change only what the sprint disproved or sharpened.
2. **Cadence:** update the weekly loop with what Sprint 2 actually sustained (posts/week, batch days, the data-pull rhythm — pulls on Days 20/22/26 worked; say so).

**Deliverable:** An updated `buzzend-marketing/15-team-workflow/publishing-sop.md` reflecting Sprint-2 reality, change note in READY/.

## Task 2 · 🟡 Archive the Sprint-2 working files (40–50 min)

**Why:** Same rule as Day 15: nothing deleted in anger, nothing stale posing as current. Whoever plans Sprint 3 should open folders that only contain living documents.
**Where:** `buzzend-marketing/17-archive/` + the folders holding Sprint-2 working files.
**Tools:** Code editor, git, `buzzend-marketing/17-archive/README.md` (the conventions and table).

**Steps:**
1. Sweep the Sprint-2 working files and sort each into KEEP-LIVE or ARCHIVE:
   - **Stays live:** the Growth Tracker (including `Sprint2-Baseline` and `Sprint2-Results` — they're history the next baseline needs), `publishing-sop.md`, `12-community/where-were-welcome.md`, `12-community/how-to-invite-friends.md`, everything in `14-weekly-reports/`.

3. Move each archived file into `buzzend-marketing/17-archive/` and add its row to the README table: file, date, one-line reason ("superseded by Sprint2-Results, Day 30").
4. Do NOT archive anything another doc still links to — check first, fix the link or leave the file.
5. Close the loose ends in the tracker while you're sweeping: gym rows still quiet after the Day-27 bump get status "no response — closed".
6. Commit with a message listing what moved, and drop a one-liner in team chat so nobody hunts for a moved file next week.
