## Task 1 · 🔥 Write the repeatable publishing SOP from what actually happened (100–120 min)

**Why:** "End the 15 days with a repeatable process" was the sprint's stated goal from day one. The playbooks say how things SHOULD work; this SOP records how they ACTUALLY worked for us — who did what, at what time, with which tools — so next sprint (or a new person) runs week one without re-learning anything.
**Where:** New file `buzzend-marketing/15-team-workflow/publishing-sop.md`.
**Tools:** Code editor, Growth Tracker, `buzzend-marketing/15-team-workflow/production-pipeline.md`, `buzzend-marketing/16-templates/workflow-templates.md` (checklist #8), your Day-12 "Android checks" list.

**Steps:**
1. Create `buzzend-marketing/15-team-workflow/publishing-sop.md`. Open with one line: "This is what we ACTUALLY did for 15 days — not theory. Update it whenever reality changes."
2. **Roles as they really settled:** who recorded, who edited, who published, who replied to comments — by name (Avinaya/Gaurab/Riya), with the real handoffs (e.g. edit → Avinaya's approval pass → publish). Where reality differed from `production-pipeline.md`'s 14 stages, write what we did and why it worked.
3. **Tools:** the exact tools we used at each stage (recording phones, editor, Canva, the consoles, the Growth Tracker tabs) — the real list, not a wish list.
4. **Times:** the posting times we actually used per platform, updated with the Day-12 timing-experiment verdict (get it from Avinaya after the retro — if the new slot WON, the SOP ships with the new slot).
5. **The per-post checklist:** paste checklist #8 from `workflow-templates.md` and extend it with what the sprint taught us — your Android device checks from Day 12, the caption-legibility rule, the link-tap test, the one-CTA rule.
6. **The weekly loop:** what a normal week looks like (batch-film day, publish slots, Friday numbers + outreach), condensed from how our 15 days actually flowed.
7. Keep the whole thing under 2 pages — an SOP nobody reads is decoration. Link it from the tracker and in team chat.

**Deliverable:** `buzzend-marketing/15-team-workflow/publishing-sop.md` — the sprint's repeatable-process deliverable.
**Done when:** A newcomer could publish Monday's post correctly using only this doc and the files it links.
**Depends on:** Avinaya · Day 15 · Task 1 (the experiment verdicts set the SOP's posting times — draft everything else first).

## Task 2 · 🟡 Archive the sprint's working files (40–50 min)

**Why:** Next sprint starts cleaner if superseded drafts aren't mixed in with living documents. The archive rule exists so nothing is deleted in anger — but nothing stale poses as current either.
**Where:** `buzzend-marketing/17-archive/` + the folders holding sprint working files.
**Tools:** Code editor, git, `buzzend-marketing/17-archive/README.md`.

**Steps:**
1. Sweep the sprint's working files and sort each into KEEP-LIVE or ARCHIVE:
   - **Stays live:** the Growth Tracker (still the daily tool), `05-hooks/hook-bank.md`, `06-content-ideas/idea-backlog.md`, the calendar, the new SOP, everything in `14-weekly-reports/` (reports are append-only history — they never move).
   - **Archive:** superseded drafts and one-off working notes — e.g. Riya's Day-14 post draft once published, old caption drafts replaced by published versions, the Day-1 asset shortlist now that it's spent.
2. Move each archived file into `buzzend-marketing/17-archive/` and add a row to its README table: file, date, one-line reason ("superseded by published post, Day 15").
3. Do NOT archive anything another doc still links to — check first, fix the link or leave the file.
4. Commit with a message listing what moved, and drop a one-liner in team chat so nobody hunts for a moved file on Monday.

**Deliverable:** Tidied folders + updated `17-archive/README.md` table.
**Done when:** Every file in the marketing folders is either current or in the archive with a reason — nothing ambiguous.
**Depends on:** Riya · Day 15 · Task 2 (her draft can only be archived after it's published).
